# Boris Nikolić, portfolio

Personal portfolio with a terminal look: JetBrains Mono, a gruvbox dark palette, tmux-style tabs, a lualine-style status line, and an interactive shell. Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4. Live at https://bok1c4.com.

## Shell and keyboard

The hero contains a small shell (`components/Terminal.tsx`) whose commands read from `data/`: `help`, `ls work`, `open <slug>`, `git log`, `cat about.md`, `skills`, `infra`, `cv`, `neofetch`, and more. Tab completes, arrow keys browse history, Ctrl+L clears.

Keyboard chords (`components/KeyboardNav.tsx`): `g` then `h/w/e/s/a/l/c/r/d` jumps to home, projects, experience, skills, AI workflow, home lab, contact, resume, or downloads the CV; `:` focuses the shell; `?` opens the help dialog. Shortcuts are ignored while typing in a field.

## Routes

| Route | Purpose |
|---|---|
| `/` | Home: hero with the shell, projects, experience, skills, AI workflow, home lab, about, contact |
| `/resume` | The CV content rendered from `data/`, printable |
| `/Boris_Nikolic_CV.pdf` | The CV itself, a static file in `public/` |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image` | Generated by route files in `app/` |

## Commands

```bash
bun install          # install dependencies
bun run dev          # start dev server
bun run build        # production build
bun run start        # start production server
bun run lint         # run ESLint

# clean rebuild
rm -rf .next && bun run build
```

Without a local Bun or Node install, the same commands run in a container:

```bash
docker run --rm -v "$PWD:/app" -v prtf_node_modules:/app/node_modules -w /app oven/bun:1 sh -c "bun install && bun run lint && bun run build"
```

## Editing content

All copy lives in `data/`, and the site content matches the CV in `public/`:

- `site.ts`: canonical URL, site name, title, and description (also the Open Graph values).
- `personal.ts`: contact details, the hero tagline and sub-line, hero highlights, the summary (About and `/resume`), university, off-the-keyboard facts, the working-with-people list, principles, and the shell's `neofetch` facts.
- `experience.ts`: roles, newest first, and education.
- `projects.ts`: the four projects in CV order (problem statement, stack, highlights, repo link).
- `skills.ts`: skill groups as on the CV; secondary items are working knowledge.
- `resume.ts`: the CV file path, button label, and last-updated month.
- `ai.ts`: the "How I work with AI" section.
- `homelab.ts`: the home lab: self-hosted infrastructure and free-time projects.

Types are in `types/index.ts`.

## Updating the CV

The CV is generated from the `/resume` route, so it always says what the site says. After changing `data/`, start the site and print the route to PDF with a headless Chromium (Chrome, Edge, or Brave):

```bash
chrome --headless --disable-gpu --no-pdf-header-footer --print-to-pdf=public/Boris_Nikolic_CV.pdf http://localhost:3000/resume
```

The page carries its own print stylesheet (A4, one page, navigation hidden), so the browser's "Save as PDF" dialog produces the same result.
