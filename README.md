# Boris Nikolic, portfolio

Personal portfolio and resume with a terminal look: JetBrains Mono, a gruvbox dark palette, tmux-style tabs, a lualine-style status line, and an interactive shell. Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS v4. Live at https://bok1c4.com.

## Shell and keyboard

The hero contains a small shell (`components/Terminal.tsx`) whose commands read from `data/`: `help`, `ls work`, `cat about.md`, `cat ai-workflow.md`, `open <slug>`, `git log`, `neofetch`, and more. Tab completes, arrow keys browse history, Ctrl+L clears.

Keyboard chords (`components/KeyboardNav.tsx`): `g` then `h/a/w/l/s/e/c/r` jumps to home, ai, work, home lab, skills, experience, contact, resume; `:` focuses the shell; `?` opens the help dialog. Shortcuts are ignored while typing in a field.

## Routes

| Route | Purpose |
|---|---|
| `/` | Home: hero, selected work, about, capabilities, experience, contact |
| `/work/[slug]` | Two work pages (`fairphone-odoo-platform`, `toy-store`) |
| `/resume` | Print-optimized, ATS-friendly resume rendered from `data/` |
| `/resume.pdf` | Static PDF, regenerated from `/resume` (see below) |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image` | Generated by route files in `app/` |

## Commands

```bash
bun install          # install dependencies
bun run dev          # start dev server
bun run build        # production build
bun run start        # start production server
bun run lint         # run ESLint

# clean rebuild
rm -rf .next && bun run build
```

Without a local Bun or Node install, the same commands run in a container:

```bash
docker run --rm -v "$PWD:/app" -v prtf_node_modules:/app/node_modules -w /app oven/bun:1 sh -c "bun install && bun run lint && bun run build"
```

## Editing content

All copy lives in `data/`:

- `site.ts`: canonical URL, site title and description.
- `personal.ts`: contact details and positioning (headline, supporting statement, about paragraphs, capabilities, principles, "Currently" facts).
- `skills.ts`: capability groups with a usage line and primary/secondary items.
- `experience.ts`: the story timeline (site), the detailed role (resume only), education.
- `projects.ts`: the six case studies and the "More work" list. Adding an object to `caseStudies` creates a new `/work/[slug]` page.
- `resume.ts`: resume-only copy (summary, skill lines, projects).
- `ai.ts`: the AI-workflow section (loop, prompting practices, Claude Code setup, MCP servers, environment).
- `homelab.ts`: the home lab section, rendered like `systemctl status`.

Types are in `types/index.ts`. Diagram content for case studies lives in `components/diagrams/index.tsx`.

## Regenerating the resume PDF

Start the site (`bun run dev` or `bun run start`), then print the `/resume` route to PDF with headless Chrome:

```bash
chrome --headless --disable-gpu --no-pdf-header-footer --print-to-pdf=public/resume.pdf http://localhost:3000/resume
```

`chrome` is the Chrome or Chromium executable for your platform. The page carries its own print stylesheet (A4, no navigation), so the browser's "Save as PDF" dialog produces the same result.
